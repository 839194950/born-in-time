**Goal:** 交付一个可在浏览器完整玩一局（抽出生年份 → 一生推进 → 死亡 → 结局卡/复盘）的像素风中文人生模拟静态站，可部署到 Vercel 或 Cloudflare Pages。

**Architecture:** 引擎层是与框架无关的纯 TypeScript（种子随机、时间推进、窗口判定、账本、命型判定），React 仅做渲染与订阅；所有事件、道具、称号、人口数据放在 `data/` 配置层，新增内容不改引擎。引擎不依赖 DOM，因此可以在 Node 里以 TDD 方式跑完整局。

**Tech Stack:** Vite 5 + React 18 + TypeScript 5 + Vitest；零运行时依赖（除 React）；结局卡用 Canvas 2D；存档用 localStorage。

**Spec:** `生逢其时-完整规格.md`

## Global Constraints

- 出生年份范围 **1977–2002**，超出范围不得生成。
- 五维数值 `health/ability/wealth/family/happiness` 恒在 **0–100** 闭区间。
- 时间推进：1× 下 **1 年 ≈ 4.5 秒**；倍速 1/2/4/8/16；支持暂停、快转到下一抉择、自动抉择。
- 一局实际弹出的抉择总数 **约 20 个**，总时长 **6–8 分钟**。
- 所有事件必须带 `source` 出处行；无出处的事件不得进目录。
- 未来推演内容（出生队列后半生）文案必须标注“推演”。
- 只陈述际遇与统计，不做价值判断；不渲染血腥画面；不做自伤内容。
- 零后端、零账号；存档只用 localStorage；不得引用原作 1in8b.life 的文案/数据/素材。
- 移动端优先（竖屏可用），场景区与数值区可上下堆叠。
- 像素美术：角色画布 48×64、场景 960×540，整数倍放大，`image-rendering: pixelated`。

## Review Focus

1. **2002 年出生、活到 2060 年以后**：事件表在那之后没有内容，推进不能卡住、不能空白刷屏，必须有推演收尾与确定的终点判定。（Task 11 的 2002 队列用例）
2. **同一事件在一局内重复触发**（跨年份/跨窗口）：人生纪录与账本不能出现重复条目。（Task 8、10）
3. **抉择弹窗打开时刷新页面或切换倍速**：恢复后不能丢事件、不能重复结算同一年。（Task 17 的“待抉择时存档→恢复→重放到同一事件”用例）
4. **置灰选项被点击/键盘回车确认**：必须只提示原因，绝不产生数值变化或写入纪录。（Task 11 的锁定选项用例 + Task 16 手工验证）
5. **localStorage 被禁用、写满、或存有旧版本 schema**：不能白屏，必须降级为“本局可玩但不存档”。（Task 17）

### Task 6: 时代窗口判定（月级精度）

**Files:**
- Create: `src/engine/window.ts`
- Test: `tests/engine/window.test.ts`

**Interfaces:**
- Produces:
  - `judgeWindow(input: { birthYear: number; birthMonth: number; eventYear: number; windowAge: [number, number]; edgeYears?: number; secondWindowAge?: [number, number] }): WindowJudgement`
  - `WindowJudgement = { verdict: Verdict; age: number; ageMonths: number; gapMonths: number }`
  - `verdictText(verdict, gender): string`（“赶上 / 差一年 / 路过”）

规则（必须与规格 §6.1 一致）：
- `ageMonths = (eventYear − birthYear) × 12 + (eventMonth − birthMonth)`，`eventMonth` 固定取 `6`（年中判定，代表该年事件的平均时点）。
- 窗口换算为月：`[minAge×12, maxAge×12 + 11]`。
- 命中 → `caught`, `gapMonths = 0`。
- 未命中但在 `edgeYears×12` 个月内 → `nearMiss`，`gapMonths = 距最近边界的月数`。
- 其余 → `passedBy`。
- 有 `secondWindowAge` 时，取两个窗口中最近的判定。

- [ ] **Step 1: 写失败测试**

```ts
// 1979-12 出生，1999 年扩招窗口 [17,19] → 19 岁，赶上
expect(judgeWindow({ birthYear: 1979, birthMonth: 12, eventYear: 1999, windowAge: [17, 19] }).verdict).toBe('caught');
// 1980-08 出生，1999 年 → 18 岁零 10 个月，仍在窗内
expect(judgeWindow({ birthYear: 1980, birthMonth: 8, eventYear: 1999, windowAge: [17, 19] }).verdict).toBe('caught');
// 1981-09 出生，1999-06 时 17 岁 9 个月，窗口下界 17 → 赶上
expect(judgeWindow({ birthYear: 1981, birthMonth: 9, eventYear: 1999, windowAge: [17, 19] }).verdict).toBe('caught');
// 1982-09 出生，1999-06 时 16 岁 9 个月，距下界 3 个月 → 差一年，gapMonths=3
expect(judgeWindow({ birthYear: 1982, birthMonth: 9, eventYear: 1999, windowAge: [17, 19] })).toMatchObject({ verdict: 'nearMiss', gapMonths: 3 });
// 1990 年生，1999 年 → 9 岁，距 17 岁差 8 年 > edge 3 年 → 路过
expect(judgeWindow({ birthYear: 1990, birthMonth: 3, eventYear: 1999, windowAge: [17, 19] }).verdict).toBe('passedBy');
// 超上界 2 年 → 差一年（edgeYears 默认 3）
expect(judgeWindow({ birthYear: 1974, birthMonth: 3, eventYear: 1999, windowAge: [17, 19] }).verdict).toBe('nearMiss');
```

- [ ] **Step 2: 运行确认失败** → FAIL
- [ ] **Step 3: 实现**（边界用 `<=`，禁止浮点误差：全部用整数月计算）
- [ ] **Step 4: 运行确认通过** → PASS

家人：`start()` 时按 `birth` 生成父母与兄弟姐妹（父母年龄 = 主角年龄 + 24~32 的固定偏移，写进 `birth` 之外的快照）；`resolve()` 写入 `flags` 后，若出现 `married` 就补 `spouse`，出现 `child_born` 就补 `child`。家人只用于渲染与亲情文案，不参与数值结算。

推进一年的固定顺序（必须实现为这个顺序）：
1. `year += 1; age += 1`
2. 应用 `healthDecay(age)` 与 `applyFocus`
3. `wealthGain` 修正（focus 的财富增量走折扣）
4. `adaptHappiness`
5. 写入 `YearSnapshot`
6. `findDueEvents` → 若有事件：记录账本条目，`phase='awaitingChoice'`；死亡判定延后到次年
7. 年龄 ≥ 死亡年龄 → `phase='dead'`

`resolve(choiceId)`：校验选项存在 → 若 `locked` 则抛 `Error('locked')` 且不改变任何状态 → 应用 `effects` → 若有 `probability` 按 `rng` 抽分支 → 写 `flags`/`timeline` → `phase='playing'`。
