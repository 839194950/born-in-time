## 一、出生年份范围：1977–2002 → **1958–2005**

**改动来源**：用户实机试玩后提出「出生基本都集中在 1980–2000，内容太少，区间改大一点」。

**规格原文**：§0 第 2 条「出生年份范围：1977–2002（改革开放后；更早年代不做）」，并标注“不得变更”。
本次按用户明确要求覆盖该条。

**为什么选 1958 和 2005**：
- 1958 年出生的人在 1977 年 19 岁，正好撞上恢复高考——这是本作宣传语“从恢复高考那年开始抽”真正对应的那一批人。
- 1958–1975 年出生的人在 1990–1998 年正值壮年，能让「股市开市」「民工潮」「粮票作废」「包分配终结」「下岗」「房改」这些原本永远够不着的窗口真正可被赶上。
- 2005 年出生的人可以走到 2060 年代的推演段。

**连带改动**：
- `src/engine/types.ts` 的 `YEAR_FROM` / `YEAR_TO`
- `src/data/demography.ts` 补 1958–1976、2003–2005 的城镇化率、出生人口、预期寿命
- `src/data/names.ts` 补 1958–1976 姓名段（建国、卫东、桂兰、秀兰…），最后一段延长到 2005
- `src/data/yearNotes.ts` 补 1958–1976、2003–2005 的“这一年”

## 二、出生年份抽签权重：人口数 → 人口数的平方根

**原因**：直接按出生人口加权会让 1963（2950 万）和 1987（2550 万）形成两个尖峰，两头几乎抽不到，扩大范围也解决不了“老是那几个年份”。

**做法**：`yearWeight = Math.sqrt(出生人口数)`，峰谷比从 1.9 倍压到 1.35 倍。

**代价**：年份分布不再严格等于真实人口比例。规格 §3.1 说的是“量级加权”，仍属其许可范围。

## 三、称号判定阈值

| 称号 | 规格 | 实现 | 原因 |
|---|---|---|---|
| 每次都差一年的人 | 差一年 ≥3 次 | **比例判据：≥4 次且占"够到的窗口"≥40%** | 事件窗口密度高于规格假设。先收窄带宽（`edgeYears` 3 → 2）把命中率从 24.8% 压到 6.7%，但那一轮之后"同年撞车不再丢弃"让账本条数变多，绝对阈值重新失真（`nearMiss >= 5` 又回到 11.3%）。改用比例：绝对次数不说明"每一次"，**够到的门里四成以上是差一点关上的**才叫"每次都差一年"。实测 6.8% |
| 比同龄人多活十年的人 | 享年 ≥ 队列预期寿命 +10 | **+10（已回到规格原文）** | v1 曾降到 +1.5 迁就分布，结果既让称号名撒谎、又仍是 0%。v2 改为打开分布上尾，这条偏离**作废** |
| 最后一班车的人 | 末班车型命中 ≥2 次 | **≥2 次，或 ≥1 次且赶上 ≥6 次** | 房改限定城镇后，单次命中已属少见；加了后半个条件避免它与“每次都差一年”抢同一批人 |

称号名称、稀有度顺序、判定优先级均未改动。

## 四、年度重心效果按 0.4 折算

**规格**：§5「每项效果为小幅（±1–3）」。数据里写的仍然是 ±1–3。
**实现**：每年实际生效值 = 数据值 × 0.4，**按钮上显示的是折算后的真实值**（因此会出现 `能力 +1.2` 这种小数）。

**原因**：重心是每年都结算的，连选 40 年“拼事业”，-2 × 40 = -80 会把人直接推到 0，后半生没有余地。

## 六、房改与包分配的「末班车」规则

- 房改（1998）加了 `conditions: { urban: true }`：福利分房只存在于城镇单位体系，农村玩家不该被算作“赶上末班车”。
- 父母单位分房（1997）设置的是 `family_home` 而不是 `has_home`：那是父母名下的房子，不该让玩家因此错过自己的人生第一套房。
- 包分配（1996）新增为独立事件，带 `lastTrain`，窗口 21–24 且需要上过大学。

## 七、条件专属事件不判定“路过”

`src/engine/game.ts`：`layer === 'conditional'` 的事件一律按 **赶上** 处理。
理由：条件专属是“你身上确实发生过的事”，不存在“路过”一说；`windowAge` 只用于核验表标注建议年龄。

---

## 八、死亡年龄算法

**规格 §4.1**：终点年龄 = 队列预期寿命 ±（健康终值映射修正 ±8）± 随机（±4）。
**实现**：死亡基准只在开局抽一次（队列预期寿命 ±4），健康修正每年按**当前健康**现算（±6），每年重判。

**原因**：若开局一次性算死，健康数值对寿命就没有任何影响，规格要的“健康修正寿命”会失效。

---

## 九、存档：重放而不是快照

存档只存 `种子 + 出生 + 已发生的事实流水`，恢复时用同一种子重放。
**原因**：避免“弹窗打开时刷新”导致事件丢失或重复结算。恢复后数值与账本必须与原局完全一致，不一致就当存档不可信丢弃。

---

## 十、美术：canvas 程序化像素绘制，不是 PNG 素材

角色与场景由 `src/ui/lib/pixel.ts` / `scene.ts` 在 canvas 上按 48×64 / 960×540 的像素格绘制，全局调色板约 34 色。
**原因**：48×64 网格上 AI 生成无法保证一致，程序化绘制能保证风格统一且零素材体积。
**换手绘的接口**：只改 `src/ui/components/SceneStage.tsx` 与 `src/ui/lib/scene.ts`，数据层不用动。

---

## 十一、其他小项

- 窗口判定取“年中”作为事件时点（6 月），因此“差 11 个月”这类文案可以逐月精确。
- 同一年最多弹一个抉择；判定为“路过”的事件不占名额，只写一行播报。
  超出名额的**不丢弃，顺延**到这次抉择之后（`pendingQueue`，§18.2）。
- 事件目录在测试里强制校验：id 唯一、必须有出处、必须有选项或标 broadcast、2026 年后必须写“推演”。

## 十二、v2 的改动（2026-10-22，四批优化）

这一批改动很大，逐条记下来，免得后来人当成 bug 改回去。

### 12.1 视觉：暗炭底 → 暖纸底
参照物是 1in8b.life。调色板整体重写（`src/ui/lib/pixel.ts`，约 50 色）；场景统一到 3px 像素网格
（960×540 = 320×180 个场景像素，与角色 scale 3 同密度）；角色改 chibi + 1px 暖褐描边；桌面 ≥1024px 双栏。

### 12.2 节奏：一局抉择 52 → 24（规格目标 20）
- `EventDef` 新增 `priority`：>= 3 才弹窗，< 3 只写一行播报。
- 24 个阶段事件只留 8 个弹窗，其余 16 个降级为播报。
  **（2026-10-24 已改：11 个弹窗 / 13 个播报，且降级要按默认项结算后果，见 §18.1）**
- 日常小事：连续 ≥3 年无弹窗才补一件，一生上限 4 件。
- 反思节点 5 处 → 3 处（18/40/60）。

### 12.3 数值
- 健康衰减三档全部减半；新增 `healthBand` 与 `healthRecoverBoost`（低于上限时正向健康 ×2.2，且必须主动选）。
- 55 岁后能力 −0.5/年、亲情 −0.35/年。
- 长寿尾 `min(8, 养生年数 × 0.4)`，让「多活十年」成为可经营的 build。
- 财富阻尼：事件收益只在前 30% 时减半；年度漂移仍从 45 百分位起打折。

### 12.4 存档：版本 2 + 目录指纹
- `SAVE_VERSION = 2`、`SAVE_KEY = 'sfsq.current.v2'`（旧档留在原 key，不删）。
- `SaveV1.ch` 存事件目录指纹，对不上判 `stale` 并明确提示，而不是静默吞掉。
- `loadCurrentStatus()` 三态：ok / empty / stale（另有 corrupt）。

### 12.5 分享：一局 = 一个种子
v1 有两个互不相关的种子（出生一个、对局一个），「这一局」无法被任何标识指向。
现在出生也由同一颗种子推出，链接 `?s=<base36>`，结局卡页脚印二维码（白板 246）。

### 12.6 音频：零素材，全部 Web Audio 合成
8 个 cue，无音频文件；死亡时刻先静默 1.2s 再「关机」（守 §10-1）。
默认开、音量 0.35、独立静音开关。首个 cue 必定在「就这一年，开始」之后——抽签滚动没有手势，注定静音，这是预期不是缺陷。

### 12.7 新增：际遇图鉴与最小埋点
图鉴跨局累积「赶上过哪些时代窗口」；埋点 8 个事件、零后端，暴露到 `window.__SFSQ__`。

## 十三、v2.1 的改动（2026-10-22，第二轮）

### 13.1 史实：90 条全部核到官方来源

原先 82 条「待核」，其中还包括这一轮新增的 9 条。已逐条上网核对，结论写进
`scripts/gen-fact-table.ts` 的 `VERIFIED` 表（不是手改 Markdown，重跑不会丢）。

查出并修正的 4 处事实错误：

| 条目 | 原来 | 实际 |
|---|---|---|
| `era_tier1_house_2017` | 「一线房价再上一层」，暗示 2017 年还在暴涨 | 317 新政后 15 个热点城市环比**首次全面停涨**。改为「一线的门关上了」，选项换成「赶在关门前签」/「回老家买」 |
| `era_stock_crash_2015` | 「几周里跌去了大半」 | 5178→2850，**两个多月、44.95%**。改为「两个多月里跌去了四成多」 |
| `era_crypto_2013` | 「从几十美元涨到一千二，又跌回四百」 | 10 月底已 200–300 美元，高点约 1240，随后跌到 640。改为「从两百多美元涨到一千二，一个月后又跌回六百」 |
| `era_mobile_pay_2014` | 「年底街边的摊子开始贴二维码」 | 2014 年 3 月央行曾暂停二维码支付，大规模铺开在 2016 之后。改为「有些店里开始贴二维码」 |

### 13.2 角色：`happiness` 从「传进来没人读」变成真的影响表现

v1 把 `happiness` 一路传进 `drawCharacter`，函数体里一次都没用过，`is-happy` 还是个 CSS 里不存在的死类名。
现在：

- `happiness >= 68`：弯眼（眼尾上挑）+ 三段式上翘的嘴 + 更宽的腮红
- `happiness < 40`：眼睑下垂（只画下半）+ 嘴角向下，不画腮红
- 健康 < 30 时手垂得更低（`armDrop`）
- `breath: 0 | 1` 两帧呼吸，只动上半身，腿脚是站定的锚；1.1 秒交替一次；`prefers-reduced-motion` 时静止

### 13.3 定格画面：从全黑遮罩改成场景底

`.still` 原来是 `rgba(10,9,7,0.9)` 的全屏遮罩 + 三行白字。注释写的是「用场景底 + 排版做出停顿感」，
实现却连场景都没画。现在用当下这一刻的 `SceneStage`（`variant="plain"`）做一条宽银幕横带，
暖色暗角收边，文字落在画面下方。横屏场景塞进竖屏不 cover、只按宽度铺满，人始终完整。

### 13.4 死亡屏：先暗下去，再出字

最后一帧在原地用 1.6 秒淡到黑（`brightness 0.92 → 0.08`），文案延迟到 1.3 秒后才出现。
和音频方案的「进死亡屏先强制静默 1.2 秒」是同一个节奏。

### 13.5 弹窗内嵌五维读数

移动端弹窗是底部抽屉（约 46% 屏高），会把页面上的五维条盖掉一半——而玩家正要看它做选择。
现在弹窗内有一行紧凑读数（标签 + 值 + 3px 迷你条），配色沿用 `.stat-*`。

### 13.6 门槛：`statMin` 抬到分布中位数附近

v1 的 `ability: 40–55` 相对能力终值（P50 ≈ 70）形同虚设，只有 29.6% 的局能见到置灰选项。
现在 ability 35→46 / 40→52 / 45→58 / 50→62 / 55→68，wealth 35→42 / 40→48。
实测：见到置灰选项的局 **79.9%**，置灰选项占比 4.61%（每局约 1 次），12 个称号仍全部可达。

### 13.7 其他

- 墙上挂画改成「全家福 + 奖状」（原来是一小块草 + 两条灰线，手机上读不出是什么）
- 室外人物脚部下移到地平线之前（原来腿的下半截被栅栏切掉，人看起来像跪着）
- 结局卡幸福曲线纵轴按本局实际范围自适应

## 十四、v3 的改动（2026-10-22，第三轮：界面语言）

参照 1in8b.life 的界面重做版式。**结论记在这里，免得后来人以为「只是换了配色」**：

v2 的「暖纸底 + 6px 厚白框 + 10px 圆角 + 投影 + 大圆角按钮 + 彩色胶囊 + 34px 大标题」，
即使换成别的颜色也仍然会被读成"AI 味"。廉价感的来源是版式：圆角与描边太重、字号层级倒挂、
装饰元素太多、留白没有节奏。参考图的成本几乎全在版式上，不在颜色上。

### 14.1 版式规则（v3 覆盖层，写在 global.css 末尾）

| 维度 | v2 | v3 |
|---|---|---|
| 页面底 | 暖米色 #f6f0e4 | 中性浅灰 #f6f6f4 |
| 卡片 | 6px 厚白框 + 10px 圆角 + 阴影 | 1px #e7e7e3 + 4px 圆角 + 几乎无阴影 |
| 字号 | 正文 13-15px、标题 34px | 正文 12px、卡片标题 13px、元信息 11px |
| 顶部 | 大年份 + 一排大按钮 | sticky 工具条（44px），小方块按钮 26px 高 |
| 布局 | 双栏 | 三栏 252 / flex / 296（≥1180px） |
| 强调色 | 砖红 #a63b30 | 低饱和深红 #8c2f39 |
| 状态标签 | 彩色胶囊 | 灰底灰字小标签 |

### 14.2 新增的界面元素

- **身份证卡**：深红标签条 + 像素头像（复用 `drawCharacter`，`src/ui/components/Portrait.tsx`）+ 身份信息表 + 哈希串
- **背景卡**：同年位次 / 家境 / 出生时城镇化 / 同批人预期寿命
- **人生地图**：一格一年。深红＝赶上时代窗口，浅红＝差一年，灰阶深浅＝当年幸福
- **「今年的重心」的处境说明**（`stageHint(age)`）：告诉玩家当下是什么处境、选重心有什么用

### 14.3 像素场景升级

- 远山改成独立的蓝灰两档（`PALETTE.hillFar` / `hillFarDark`）——原来和草地同色，像两片草地叠在一起
- 人物整体放大（`STAGE_SCALE` 从 0.58–1.00 提到 0.72–1.22）——原来腿短到看着像跪着
- 加 **电线杆 + 下垂的电线**（`powerPole`）、**背景路人**（`bystander`）：院子不再只有自家人

### 14.4 顺带修掉的两个真实缺陷

1. **定格画面的 z-index（60）高于事件弹窗（40）** —— 定格那 2.2 秒里玩家点不到任何东西，
   自动化脚本也会因命中检测失败而一直等。已把 `.still` 降到 35，弹窗优先。
2. **置灰选项排在第一位** —— 玩家一进弹窗先看到的是点不动的按钮。门槛提高后（13.6）置灰项变多，
   这个问题被放大。现在能选的排前面、置灰的排后面。

### 14.5 结局卡

配色与页面统一（`INK #2b2b29` / `PAPER #f6f6f4` / `ACCENT #8c2f39`）——原来是米黄 + 砖红，
和浅灰白 + 深红的页面并排放像两个产品。

## 十五、v4 美术：程序绘制 → 模板派生生图（2026-10-23，§十作废）

  生图编辑每组开干净会话、特征词禁写身材/大小词、逐张量比例验收。
- 背景板 20 张（8 场景×可达时代），与人物同族扁平风，时代色调胶片土褐/挂历暖橙/数字冷蓝。
- 身份证证件照 42 张（7 套×6 段），与场景精灵同套同段索引。

## 十六、移动端新增：年份进度条（2026-10-24，规格外新增）

规格没有"本年内进度"这个元素。主循环屏吸顶工具条下新增一行进度条：与 tick 同步、200ms 步进，
暂停或等抉择时冻结；一年时长 = `YEAR_MS / speed`（`YEAR_MS = 60000`）。同期修掉两处移动端显示问题
（倍速选中态被点按高亮洗白、身份证"生"印压住最后一行信息），均属 bug 修复、不记为偏离。

## 十七、2026-10-24 缺陷修复（不改规格，只列与规格/旧实现相关的口径变化）

这一轮以修 bug 为主，以下是**判定口径发生变化**的几处，避免后来人当成新 bug 改回去。

### 17.1 时代窗口判定：从月龄改为整年

**旧口径**：`ageMonths = (事件年 - 出生年) × 12 + (6 - 出生月)`，窗口按 `[minAge×12, maxAge×12+11]` 判。

**问题**：事件时点固定取年中（6 月），12 月出生的人在窗口下界那一年还没过生日，
于是每一个窗口都被系统性判成"差几个月"。实测 nearMiss 占比：1 月 14.3% / 6 月 14.3% / **12 月 19.0%**。
同一件事，对年末出生的人天生更难够到。

**新口径**：`ageYears = 事件年 - 出生年` 决定"在不在窗口里"；`ageMonths` 仍返回，但只作参考。
实测 1/6/12 月均为 5.0%，极差 0pp。

**代价**：不再有"只差了 11 个月"这种精度，只有"差 1 年"。换来的是出生月份不再影响一个人的命——
这个游戏抽的是"出生在哪一年"，不是"生在哪个月"。

### 17.2 「差一年」带宽：`edgeYears` 3 → 2

见第三节。实测平均 nearMiss 3.0 → 2.1，称号命中 24.8% → 6.7%。

### 17.3 学历：补「专科」档

`stage_gaokao` 的「报专科」以前不设任何 flag，于是专科毕业生在 `deriveCareer` 里等同没上过大学
（落到"普通职工"）。现在设 `junior_college` + `higher_ed`，职业推导新增「技术员」一档（1.05 倍均薪以下）。

同时 `stage_graduation`（21 岁）加 `conditions: { flags: ['higher_ed'] }`：
以前它没有任何条件，约四成没上大学的玩家会在 21 岁读到"毕业前那几个月，宿舍里的人都在讨论去哪"。

### 17.4 阶段事件加年份闸门

新增 `EventDef.yearRange`。`stage_gaokao` 限定 `[1977, 9999]`：
统一高考 1977 年冬才恢复，而 1958 年出生的人 18 岁是 1976 年——
以前会在 1976 年"参加高考"，紧接着 1977 年又赶上"恢复高考"，连着考两次。

### 17.5 称号顺序与稀有度

- `守一座城的人`：判据保持 `moves === 0 && jobChanges <= 1`（一生只干过一份工作、没离开过），
  但实测命中约 19%，属**常见命型**，rarity 4 → 3，并排到「过小日子的人」之后，只吃前者剩下的份额。
- `高开低走的人`：`finalWealth < 52` → `< 60`。wellOff/rich 出身的初始财富就有 83，跌到 52 以下几乎不可能（0.2%）。

### 17.6 存档：`phase` / `pendingEventId` / `focusLog`

`SaveV1` 新增三个字段（均可选，不升 `SAVE_VERSION`）：

| 字段 | 作用 |
|---|---|
| `focusLog` | 年度重心变更流水，`year` 是**生效年份**（tick 先 `year += 1` 再结算） |
| `phase` | 存档那一刻是 `playing` 还是 `awaitingChoice` |
| `pendingEventId` | 存档时正开着的弹窗 |

没有 `focusLog` 就无法重放（重放会全程用默认重心，数值必然对不上）；
没有 `phase` / `pendingEventId`，同一年有多个弹窗时（事件 → 反思 → 排队）补不准确。

另外**删掉了"账本 choiceId 也入队"的旧逻辑**：同一个时代事件被入队两次，
"队列里还有值"变得不可靠，重放时会替玩家把没选过的弹窗选掉（实测多算 1 点健康）。

### 17.7 `Game` 的随机流消耗

`new Game({ seed })` 会先抽一次出生再抽家人；`new Game({ seed, birth })` 直接抽家人。
同一个种子会因为"怎么进来的"生成不同的人生，而存档重放走的正是后者。
现在传入 birth 时也照样把 `rollBirth` 消耗掉，两条路径一致。

### 17.8 1958–1976 的内容定位

这 19 个年份的玩家在那段历史里**只能是孩子**，所以不做成"你的人生抉择"，而是"家里的抉择落在你身上"：
1960 粮本怎么分、1968 哥哥姐姐走不走、1970 谁被推荐上大学。年代氛围走播报层（6 条）。
同年出生的人窗口一致，所以这几条只用 `windowAge` 卡年龄段，不做年份闸门。

## 十八、2026-10-24 第二轮缺陷修复（v6）

复查发现的问题不在"某个数值不对"，而在**两条静默丢弃规则**：一条把选项扔掉，一条把事件扔掉。
合起来的效果是——**77.9% 的玩家一辈子没有孩子，36.9% 的人从没见过"结婚"这个抉择。**

### 18.1 播报级事件要结算后果，不能只写一行字

`priority < 3` 的事件走 `continue`，此前**只写一行播报，选项里的 effects / setFlags 全部丢弃**。
16 个阶段事件的 35 个选项、209 点属性、`child_born` 等 flag 因此成了死代码：
「生孩子」不结算 → 孩子只能靠 2016 年「全面二孩」那条时代事件出现（实测 22.1%）；
「四年级」不结算 +3 能力 → 15 岁能力均值被压到 44.7，而"读高中"的门槛是 46。

现在 `settleSilently()` 按 `default: true` 那一项结算，理由：默认项在数据里本来就是
"没人特意去选、但日子会往这边走"的那一项，正好承接"这件事发生了，只是没让玩家停下来拍板"。
概率型选项不掷骰子（取第一个分支），**播报级事件不消耗随机流**，否则同一个种子会因降级与否整条时间线错位。
时代事件不走这条：它讲的是"大事发生那年你几岁"，降级就该只是一行背景音。

**数值按 0.4 折算（`SILENT_SETTLE_SCALE`）并走 `applySoftEffects`**。全额结算会把「亲情」均值顶到 87
（P10 79 / P90 94）——一条所有局都贴天花板上的轴等于没有这条轴。折算的是"力度"，不是"有没有发生"：
flags 一律照常结算，所以孩子、房子、离婚一个都不会丢。

### 18.2 同年撞车要顺延，不能丢

`MAX_DECISIONS_PER_YEAR = 1` 之后曾经直接 `break`：剩下的事件既不弹窗、也不留播报、
下一岁也不会再触发（年龄触发器只匹配一次）。123 组「生年 × 年龄」撞车组合里，
`stage_marriage` 丢 36%、`stage_first_job` 丢 26%，`era_housing_reform_1998` 丢 63%。
根因是 era 事件权重（4–6）普遍压过 stage（2–4），**撞车时永远是人生节点先死**。

现在改成 `pendingQueue.push`——反思节点一直在用的队列，不是新机制。顺带把
"队列非空就跳过反思节点"的旧判断去掉：那个判断会吞掉一个设计上必出的节点。

### 18.3 三个节点提回弹窗，三条推演事件降为播报

抉择预算是零和的。取舍标准：**这件事有没有"值得玩家拍板"的岔路**。

| 提升到 priority 3 | 理由 |
|---|---|
| 毕业去向（21） | 「留大城市还是回老家」，且两个选项分别设 `migrant` / `stable_job` |
| 孩子（30） | 中年唯一不可逆的节点，也是孩子/学区房/孙辈整条线的总开关 |
| 家里出了点事（58） | 情绪浓度最高的岔口，`apart` 会设 `divorced` |

降到 priority 2：`era_longevity_2040` / `era_ai_society_2045` / `era_carbon_2035`——
推演型生活切面，选项只是态度差异，没有真正的岔路。

代价：一生抉择 22.1 → 26.2（规格 16–28，P50 26）。想让 55/75 岁那两个节点也回到弹窗，
得先再降一条无关紧要的时代事件，把预算腾出来。

### 18.4 亲情补上 sink：25 岁后开始折旧

`familyDecayAge` 55 → 25。理由不是"给多了"，而是**亲情这条轴从 25 到 55 岁没有任何 sink**：
健康一直在漏、能力 55 后漏、财富有阻力，只有亲情是只进不出（因为它的 source 以前被 18.1 吞掉了）。
source 回来之后，sink 必须跟着提前。修完 family 均值 68.7 / P10 59 / P90 78。

### 18.5 在读判定改按学制

`in_school` 在 6 岁「上学」时设上，**全目录没有一处 `clearFlags` 它**，而 `deriveCareer`
用它判"是不是学生"（`in_school && age < 24`）。于是 15 岁辍学的人到 23 岁都显示「学生」，
「第一份工资」这个里程碑被统一推到 24 岁，18–23 岁也没有一分钱财富漂移。

改成按学制判：6–14 义务教育、15–17 要真读了高中/职高、18–21 要真考上大学（含专科）。
20 岁时"学生"占比 93.5% → 37.3%。

### 18.6 复读不再是死路

`retake` 此前不设任何 flag、也没有 19 岁的第二场，比"报专科"严格更差——玩家读完
"你回到教室，又做了一年卷子"，什么也没发生。现在 `retake` 设 `retaking`，
条件层新增 `cond_gaokao_retry`（19 岁，`yearRange: [1978, 9999]`）。
放在条件层是因为阶段事件的年龄必须互不重复，而 19 岁已被「选专业」占了。
实测 2000 局里 130 次选择复读，85 次拿到 `higher_ed`（改前 0/91）。

同时 `stage_gaokao` 的 `yearRange` 下界 1977 → 1978：1977 年那一场是冬天临时恢复的特殊一届，
由时代事件独家负责。留着 1977 会让 1959 年生的人在 18 岁同时命中两条"高考"——
以前靠"一年一个名额"把阶段事件静默吞掉，改成顺延之后就会连弹两次。**把年份切开，比事后去重干净。**

### 18.7 存档指纹补上 `priority`

`catalogHash()` 原来只喂事件 id。`priority` 决定一条事件是"弹窗"还是"一行播报"，
改一次权重、同一份事实流水重放出来的结局就完全不同，但指纹不变——
这种改动会被判成"内容没变"，直到重放结束的数值比对才炸。现在 `id@priority` 一起喂。

### 18.8 已知残留（这一轮没动）

- **60 岁以后仍然没有抉择**：63/68/75 岁的抱孙子、老友、遗嘱还是播报级。要动它们得先腾抉择预算。
- `kid_tutoring` / `big_home` / `third_home` 三个 flag 仍然不可达（它们是播报级事件里的非默认项）。
- 差一年弹窗的文案三档因"整年判定"退化成两档（`gapMonths` 恒为 12 的倍数）。

### 18.9 四条事件补上"已婚 / 已有孩子"的前置条件

`era_two_child_2016`「再生一个」**没有任何 `conditions`** 就设 `child_born`。
于是选了「一个人过」的 400 局里有 **169 局凭空多出一个孩子**，还会读到
"第二个孩子出生那天，你在走廊上坐了很久"。18.1 之前这条不容易被发现，
因为 `stage_child_birth` 不弹窗、孩子本来就极少；节点恢复之后它才浮出来。

| 事件 | 补的条件 | 理由 |
|---|---|---|
| `era_two_child_2016` | `flags: ['child_born']` | "第二个孩子"以已经有第一个为前提 |
| `era_child_subsidy_2025` | `flags: ['married'], notFlags: ['child_born']` | "那就要一个"至少要已成家，且已有一个就不再是"要一个" |
| `stage_third_home`（学区房） | `flags: ['child_born']` | 正文是"孩子要升学" |
| `stage_second_home`（换大房） | `flags: ['has_home', 'child_born']` | 正文是"孩子大了，家里显得挤" |

修完：未婚玩家被塞孩子 169/400 → **0/400**。

## 十九、一条容易被误读的指标：机器人口径 ≠ 玩家行为

`balance.ts` 的 `first` 策略是"永远选第一个可用项"。「孩子」事件的选项顺序是
`要一个`（`default: true`）在前、`再等等` 在后，所以这个机器人 100% 会要孩子。
`docs` 与复查报告里凡是引用"有孩子 100%"的地方，量的都是**节点有没有弹出**，不是玩家会不会生。

同一份代码三种策略（各 400 局）：

| 策略 | 见到弹窗 | 最终有孩子 |
|---|---|---|
| `first` | 349/400 | 100% |
| 永远选「再等等」 | 349/400 | 18.2%（只剩时代事件给的第二次机会） |
| `random` | 121/400 | 33.5% |

「再等等」在 349/349 局里都可点——**"不生"这条路一直是通的**。以后写平衡报告时，
凡是涉及"玩家选择"的指标，要么给三种策略的区间，要么直接标注机器人策略，不要只写一个数。

## 二十、2026-10-25 内容扩充（v7）：把"沿时间轴的窄带"铺成"年龄矩阵"

复查时算过三张表，结论是**内容不缺，缺的是分布**：

| 生年批次 | 0–11 | 12–17 | 18–29 | 30–44 | 45–59 | 60–70 |
|---|---|---|---|---|---|---|
| 1988–1997（改前） | **0.0** | **0.0** | 2.9 | 6.7 | 1.2 | **0.0** |

48 个生年 × 0–66 岁 = 3216 个人年，其中 **68.5% 既没有时代抉择也没有播报**。
题材上，房子 8 条、加密货币 6 条、AI 4 条，而童年 0 条、晚年 0 条——
那是"投资模拟器"的内容结构，不是"人生模拟器"的。

### 20.1 分层通道：人生节点永远排在时代事件前面

`findDueEvents` 只按 `ledgerWeight` 排序，而 era 的权重普遍 4–6、stage 只有 2–4，
于是人生节点永远排在时代事件后面（第二轮"结婚被房改挤掉"就是这个排序的产物）。

现在 `channelOf()` 把事件分成两条通道：

| 通道 | 成员 | 每年上限 | 超出时 |
|---|---|---|---|
| `life` | `layer: 'stage'`，以及按年龄触发的 `conditional` | 不限 | 顺延（`pendingQueue`），**永不降级** |
| `era` | `layer: 'era'`，以及按年份触发的 `conditional` | `MAX_ERA_DECISIONS_PER_YEAR = 2` | 降级为一行播报 |

时代通道设 2 而不是 1：1998 年「房改」和「下岗」同年到期，只留一条等于让玩家
错过一生的转折（实测设 1 时 caught 从 8.0 掉到 6.5）。设 2 之后真正被降级的
只有 0.02 条/局——这个上限拦的是"同一年连弹三条时代事件"的灌新闻节奏，不是内容。

**这条通道划分管排序和节奏，不管总量。** 一生有多少次抉择由内容密度决定，
引擎不设全局上限。

### 20.2 生活切面不进账本：`ledgerWeight: 0`

新增的 26 条里，童年 16 条、晚年 6 条都是 `layer: 'era'`，按原逻辑会进账本。
实测加完之后 `caught` 从 8.0 跳到 9.3，「少年得志」「赶上每一次浪潮」直接失衡——
而这两个称号讲的是恢复高考、房改、入世那种决定了一辈子走向的窗口，
不是"2008 年你在电视前看开幕式"。

现在 `trigger()` 的账本条件是 `layer === 'era' && ledgerWeight > 0 && worthLedger`。
`ledgerWeight: 0` 成为显式标记："这件事是时代，但不是时代窗口。"
（daily / reflection 一直是 0，语义一致。）

### 20.3 新增 26 条内容

**童年 16 条**（`data/events/childhood.ts`）：1976 防震棚 / 1980 独生子女证 /
1985 第一个教师节 / 1987 前门炸鸡店 / 1990 别人的铅笔盒 / 1995 第一个双休日 /
1997 要写作文的那一晚 / 1999 千年虫 / 2001 那声"北京" / 2003 停课的两个月 /
2005 一块钱一票 / 2008 那个八月 / 2012 第一台智能机 / 2015 家里要多一个 /
2017 被收走的手机 / 2020 网课。

**晚年 6 条**（`data/events/late.ts`）：2016 异地就医备案 / 2020 扫码才能进 /
2021 上门来的人 / 2022 开户送五十块 / 2028 楼下的食堂（推演）/
2036 会说话的床头柜（推演）。

**中年 4 条**（并入 `era.ts`）：2010 招不到人 / 2013 四个小时 /

**降级 3 条**：`era_crypto_enter_2020` / `cond_btc_crisis_2019` / `cond_btc_2024`
→ `priority: 2`。币圈原本 6 条弹窗，是单一题材里最密的一串；留
2013 买、2020 峰值、2022 崩盘三个节拍就够讲完。

### 20.4 三条踩出来的教训（下次别再踩）

**一、放宽窗口不是免费的内容。** 为了让 1961–1974 出生的人在 45–58 岁不空档，
我先把股灾/P2P/延迟退休/老龄化的窗口往后拉，结果 40–60 岁被经济类事件灌满，
`lateHits` 暴涨，「大器晚成」从 2.7% 冲到 24.5%。**正确做法是补新内容，不是拉旧窗口。**

**二、称号判据会被"内容分布"证伪。** 「大器晚成」的 `lateHits >= 2` 在中年有内容
之前几乎不可达，有内容之后人人满足。判据得跟着内容一起改：
现在是 `lateHits >= 3 && lateHits > earlyHits`（晚年赶上三回以上，且比早年多）。

**三、`wealthVariance >= 200` 是个假门槛。** 这个数的中位数就是 229，
等于"比一半人稍微动一点"。加完童年事件（攒钱、买铅笔盒、去北京）之后
「折腾的人」从 24% 涨到 34%，成了最常见的一个。门槛提到 350（P75）。

### 20.5 验收（实测）

| 指标 | 改前 | 改后 |
|---|---|---|
| 童年（0–17）时代抉择密度 | 0.0–1.4 | **3.1–6.8** |
| 晚年（60–80）密度，1958–1975 | 0.0 | **2.4** |
| 最长空档 | 24 年（1965 生，33→57） | **8 年** |
| 空档 >8 年的生年 | 20 / 48 | **0 / 48** |
| 一生抉择 | 26.0 | **30.8** |
| 时代事件总数 | 41 | **67** |

三条指标都写进了 `tests/data/contentCoverage.test.ts`，以后加内容时会被挡住。

  需要 2038–2060 的第二段推演内容）。

## 二十一、2026-10-25 打磨批（v8）：播报层补空年份 + 称号分布回正

这一批不加抉择、不动平衡。三件事：补年代背景音、把称号分布从"一家独大"拉回阶梯、
修一个键盘可达性的口子。

### 21.1 播报层补 12 个空年份

改前 1958–2010 之间有 **20 个年份连一条播报都没有**，其中 1980–2010 占 10 个
（1982/1991/2000/2002/2004/2006/2007 等）。播报层 `priority` 不参与抉择名额、
不进账本、不结算数值，是补"年代感"最便宜的一层。

补了：1959 大油田 / 1973 新稻种 / 1974 兵马俑 / 1975 海城地震 / 1979 建交 /
1982 人口普查 / 1991 捐款箱 / 2000 悉尼 28 金 / 2002 世界杯 / 2004 刘翔 /
2006 农业税取消 / 2007 股市 6124。

写法一律是"那年普通人身边发生了什么"：不写"中国队首次进入世界杯决赛圈"，
写"上课时老师在讲台上放收音机，隔壁班喊起来的时候，他也停了"。
军事与政治表述一律绕开——1976 年以前不留的 8 个空年份（1962/1964/1965/1967/
1969/1971/1972/1978）是刻意从简，不是漏了。

验收：1980–2010 **零空年份**（写进 `contentCoverage.test.ts`）；
平均每条人生 64.4 条播报 + 34.4 条抉择记录 ≈ 99 条时间线。

### 21.2 称号分布：从"一家独大"拉回阶梯

`rarity` 只在测试里用（`ending.test.ts` 还锁着"数组顺序必须按稀有度降序"），
所以不能改标签，只能收紧判据。三条最松的：

| 称号 | 原判据 | 问题 | 改为 |
|---|---|---|---|
| 过小日子的人（rarity 4） | happiness≥54 && family≥55 | 幸福中位数 64、亲情中位数 68，几乎不筛人 → **40.3%** | happiness≥62 && family≥64 |
| 少年得志（7） | earlyHits≥6 | earlyHits 中位数 5，等于"比一半人多一点" → 14.4% | earlyHits≥8 |
| 大器晚成（6） | lateHits≥3 && >early | lateHits 中位数 3，筛不掉 → 9.1% | lateHits≥5 |

改完（三分策略合并 1300 局）：

| 称号 | 改前 | 改后 |
|---|---|---|
| 过小日子的人 | 40.3% | **34.3%** |
| 被时代推着走的人（兜底） | 4.9% | **18.8%** |
| 逆袭的人 | 6.8% | 6.8% |
| 最后一班车的人 | 5.7% | 5.7% |
| 守一座城的人 | 2.0% | 5.5% |
| 折腾的人 | 4.9% | 5.2% |
| 比同龄人多活十年的人 | 0.7% | 5.2% |
| 少年得志 | 14.4% | **4.7%** |
| 赶上每一次浪潮的人 | 4.3% | 4.3% |
| 高开低走的人 | 3.5% | 3.5% |
| 每次都差一年的人 | 3.4% | 3.4% |
| 大器晚成 | 9.1% | **2.7%** |

**兜底从 4.9% 涨到 18.8% 是这批里最重要的一处**：兜底称号 rarity 1，本来就该是
最常见的那一档——"时代的浪往哪边推，你就往哪边走"才是大多数人的命。
以前它只有 4.9%，是因为前面几条判据太松，把人全收走了。

遗留：`rarity` 与实际频率仍有轻微倒挂（大器晚成 2.7% 比少年得志 4.7% 更低，
但后者 rarity 更高）。这是"首个命中即返回"这条链的固有性质——排在后面的判据
会吸收前面漏下来的人。要彻底解决得改成打分制，不在这一批的范围。

### 21.3 弹窗初始焦点：无选项时不再漏

`EventModal` 的初始焦点只查 `[data-choice="available"]`。「差一年」的弹窗没有选项
（只有"继续过日子"）、全部置灰时也没有 available——两种情况下焦点都留在遮罩后面，
键盘用户既进不来也听不到"为什么选不了"。现在是"可选选项 → 退回弹窗内第一个可聚焦元素"。
